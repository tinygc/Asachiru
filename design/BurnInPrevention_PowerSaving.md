# 設計検討書 - 画面焼き付け防止・省エネ機能

## 1. プロジェクトの性質を踏まえた分析

### 1.1 利用シーンの再確認
- **目的**: 「朝の時間につけっぱなし」＝ **朝の2〜4時間程度**
- **ユーザー行動**: 身支度・朝食中 → **画面を凝視していない**（受動的な情報取得）
- **コンセプト**: 「チルい雰囲気」 → **リラックス感を損なわない**ことが最優先

### 1.2 現状の実装と Android の挙動

#### 現在の実装
```kotlin
// MainActivity.kt
window.addFlags(WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON)
```

#### FLAG_KEEP_SCREEN_ON の効果
| Android機能 | FLAG_KEEP_SCREEN_ON あり | FLAG_KEEP_SCREEN_ON なし |
|------------|------------------------|-------------------------|
| 自動スリープ | ❌ 無効化される | ✅ 設定通りに動作 |
| スクリーンセーバー（Android 14+） | ❌ 発動しない | ✅ 発動する |
| バッテリーセーバー時のスリープ | ❌ 無効化される | ✅ 影響を受ける |

**結論**: 現在の実装では、ユーザーがAndroid設定で自動スリープやスクリーンセーバーを設定しても、**このアプリ表示中は一切発動しない**。

## 2. 検討ポイント

### 2.1 現状の強み（既に焼き付け対策になっている点）

| 要素 | 現状 | 焼き付けリスク |
|------|------|--------------|
| 背景グラデーション | 時間帯で変化＋波紋アニメーション | ✅ 低い |
| ビジュアライザー | 常時アニメーション（25%透明度） | ✅ 低い |
| ニュースタイトル | 内容が定期的に変化 | ✅ 低い |
| 時計表示 | 固定位置 | ⚠️ やや高い |
| 天気アイコン | 固定位置 | ⚠️ やや高い |

**結論**: 背景が常に動いているため、**焼き付けリスクは思ったより低い**！

### 2.2 検討すべき課題

#### 課題1: Android 14のスクリーンセーバー（Daydream後継）
- Android 14以降、新しいスクリーンセーバー機能が追加
- ユーザーが有効にしていても、`FLAG_KEEP_SCREEN_ON`があると発動しない
- **対応案**: 特に対応不要（アプリの目的が「つけっぱなし」のため）

#### 課題2: 自動スリープ設定が効かない
- ユーザーがTVの自動スリープを設定していても、このアプリ表示中は効かない
- **対応案**: 特に対応不要（これがアプリの意図した動作）

#### 課題3: バッテリー消費（スマホ利用時）
- スマホでつけっぱなしにするとバッテリーを消費
- **対応案**: 
  - スマホの場合は`FLAG_KEEP_SCREEN_ON`を外すオプション検討？
  - →しかし、スマホも「朝のつけっぱなし」利用なので現状維持でOK

## 3. 結論: 現状維持で問題なし

### 3.1 なぜ現状維持でOKか

| 観点 | 理由 |
|------|------|
| **焼き付け** | 背景アニメーション＋ビジュアライザーで常に画面変化あり。時計・天気のみ固定だが、利用時間2〜4時間なら問題なし |
| **省エネ** | 朝専用アプリなので、使い終わったらユーザーがTVを消す想定。アプリ側での自動終了は不要 |
| **Androidスリープ** | `FLAG_KEEP_SCREEN_ON`で意図的に無効化。これがアプリの目的（つけっぱなし） |
| **スクリーンセーバー** | 同上。発動しないのが正しい動作 |

### 3.2 将来検討事項（優先度: 低）

もしユーザーから要望があれば検討：

| 機能 | 説明 | 優先度 |
|------|------|--------|
| ピクセルシフト | 時計・天気を10分ごとに微移動 | 低（要望があれば） |
| スリープ許可モード | 設定で`FLAG_KEEP_SCREEN_ON`を無効化できるオプション | 低（要望があれば） |

ユーザーへの説明として、以下をREADMEに追記することを推奨：

```markdown
### 💡 画面スリープについて

このアプリは「朝の時間につけっぱなし」で使う想定のため、
**アプリ表示中は画面が自動でスリープしません**。

- Android設定の「自動スリープ」や「スクリーンセーバー」はアプリ使用中は発動しません
- 使い終わったらTVの電源を切るか、アプリを終了してください
- 画面焼き付けが心配な場合は、2〜4時間程度の利用を推奨します
```

## 6. 省エネ観点での追加検討

### 6.1 現状のアニメーション・描画処理

コード調査の結果、以下のアニメーションが常時動作中：

| コンポーネント | アニメーション内容 | 頻度/Duration | CPU/GPU負荷 |
|--------------|------------------|--------------|-------------|
| **BackgroundGradientView** | グラデーション遷移 | 30秒周期 INFINITE | 中（毎フレーム描画） |
| ↳ 発光エフェクト | glowAnimationTime更新 | 毎フレーム（~60fps） | 中 |
| ↳ 波紋効果 | 3つの波紋 12-18秒周期 | 常時 | 中 |
| **VisualizerView** | 音楽ビジュアライザー | 30fps制限 | 高（FFT解析） |
| **ParticleView** | 20個のパーティクル浮遊 | 10-20秒周期 × 20個 | 中（20個のアニメーター） |
| **NewsView** | TTS点滅アニメーション | 4秒周期 INFINITE（TTS ON時のみ） | 低 |

### 6.2 省エネ改善の可能性

#### ✅ 既に最適化済み
- **VisualizerView**: 30fps制限あり ✅
- **NewsView**: TTS OFF時は点滅アニメ停止 ✅
- **ハードウェアアクセラレーション**: 有効化済み ✅

#### 💡 追加で検討できるポイント

| 改善案 | 効果 | 実装難易度 | 推奨度 |
|--------|------|-----------|--------|
| **ParticleView の描画頻度削減** | パーティクル20個が各自`invalidate()`→全体を統合して1回のinvalidateに | 中 | ⭐⭐ |
| **BackgroundGradientView のフレームレート制限** | 現状60fps想定→30fpsに制限 | 低 | ⭐⭐ |
| **波紋効果の簡略化** | 波紋3つ→1つに削減 | 低 | ⭐ |
| **FeedWatch でビジュアライザー完全除外** | ビルド時に除外（現状はVisibility.GONE） | 中 | ⭐ |

### 6.3 ParticleView の最適化案（参考）

現状の問題：
```kotlin
// 各パーティクルが個別にinvalidate()を呼ぶ → 毎秒60回×20個=1200回のinvalidate
addUpdateListener { animation ->
    x = startX + (endX - startX) * progress
    y = startY + (endY - startY) * progress
    invalidate() // ← 各パーティクルごとに呼ばれる
}
```

改善案：
```kotlin
// 親Viewでまとめて1回だけinvalidate（Choreographer利用）
private val frameCallback = object : Choreographer.FrameCallback {
    override fun doFrame(frameTimeNanos: Long) {
        particles.forEach { it.updatePosition() }
        invalidate() // 1フレーム1回だけ
        Choreographer.getInstance().postFrameCallback(this)
    }
}
```

### 6.4 結論

| 項目 | 判断 |
|------|------|
| **今すぐ対応** | 不要（現状で十分最適化されている） |
| **将来の最適化** | ParticleViewの統合invalidate化は効果あり（優先度：低） |
| **ユーザー設定** | 「省電力モード」は不要（複雑すぎる） |

**理由**: 
- 朝の2〜4時間利用では、現状の負荷で問題なし
- 過度な最適化は「チル」な雰囲気（滑らかなアニメーション）を損なう
- Android TVは通常電源接続なのでバッテリー問題なし
